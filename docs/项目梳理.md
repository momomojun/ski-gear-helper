# 滑雪装备小帮手（SkiDeals）项目梳理（全品类版）

> 这份文档讲清楚：这个工具由哪几块组成、数据怎么流动、每一块为什么这样设计。
> 对照代码看效果最好（文件路径都写在每一节里）。最后一节有“当前数据量”。

---

## 1. 一句话

**在你自己电脑上运行的滑雪装备比价工具**：从 69 家经过核验的美国网站（雪具店、户外店、品牌官网、Zappos）抓取 **22 类滑雪装备**
（双板、固定器、雪鞋、雪杖、头盔、雪镜、雪服、雪裤、手套……）的价格，识别出“同一款商品”，
在一个网页里比较各家价格、折扣、尺码库存；双板还能和日本、中国的价格对比；陌生网站可以先做可信度检测。

## 2. 整体架构

```
          ┌──────────────── 美国零售网站（69 家启用，均已核验）────────────────┐
          │ 大型零售商：evo · REI · Christy · Peter Glenn · Sun&Ski · Sports Basement │
          │ 专业店：Skis.com · Start Haus · Alpine Shop · OGE · Ski Depot · …          │
          │ 品牌官网：Black Crows · Armada · DPS · Moment · 4FRNT · J Skis · …          │
          └───────────────┬────────────────────────────────────────────────────┘
                          │ ① 抓取：每个网站 × 每个分类抓一次        skideals/crawl.py
                          │    每个网站一个“适配器”                   skideals/adapters/*.py
                          │    礼貌抓取：robots.txt、同站限速          skideals/net.py
                          ▼
                  RawProduct（标题、价格、原价、各尺码库存、所在分类页…）
                          │ ② 分类纠错：分类页里混进来的别的东西剔除  skideals/categories.py
                          │ ③ 标准化：品牌/型号/年份/性别/成色/规格/尺码  skideals/normalize.py
                          ▼
                  Listing（标准化商品 + “同款分组键” model_key）
                          │ ④ 入库（SQLite；价格有变化或满 7 天记一条历史）  skideals/db.py
                          ▼
               ┌────── data/skideals.db ──────┐
               │ listings  price_history      │◄── 可信度核验  skideals/trust.py
               │ intl_prices watchlist alerts │◄── 日本/中国比价 skideals/intl/
               │ site_checks fx settings      │◄── 汇率        skideals/fx.py
               └──────────────┬───────────────┘
                              │ ⑤ 按分类、按同款分组；算原价/折扣/历史低价   skideals/catalog.py
                              │    固定器专题：套装 vs 分开买、给板身配固定器  skideals/bindings.py
                              ▼
                FastAPI 本地服务 127.0.0.1:8765                        skideals/server.py
                              ▼
                浏览器页面（原生 JS，无需构建）                         web/
                分类栏 · 找折扣 · 型号详情 · 关注 · 网站可信度 · 购买指南
```

入口：`start.bat`（启动网页）、`crawl.bat`（手动抓取）、`python -m skideals ...`（命令行，见第 14 节）。

## 3. 22 个分类（`skideals/categories.py`）

分类是整个系统的“骨架”：抓哪些分类页、怎么纠错、尺码怎么读、有哪些专属筛选，都由这里的一张表决定。

| 大类 | 分类 | 尺码怎么读 | 专属筛选 / 特征标签 |
|---|---|---|---|
| 板·鞋·固定器 | **双板** | 长度 cm | 我的长度、类型、腰宽、含/不含固定器 |
| | **固定器** | 刹车宽度 mm | 我的雪板腰宽、DIN 上限档位、GripWalk 兼容、多标准(MNC)、登山、可调长度 |
| | **雪鞋** | Mondo 鞋码 | 我的鞋码（26.0/26.5 同鞋壳）、硬度 Flex、楦宽 Last、GripWalk、登山 |
| | **雪杖** | 长度 cm（英寸自动换算） | 碳纤维、可调节长度 |
| 防护 | **头盔** | S/M/L、头围 cm | MIPS 防旋转、耳机、一体面罩、亚洲版型 |
| | **雪镜** | 基本均码 | 亚洲版型、变色镜片、磁吸换片、附送备用镜片、可戴眼镜(OTG) |
| | **护具** | S/M/L | —— |
| 服装 | **雪服、雪裤/背带裤、连体服** | S/M/L + 数字码/童码 | GORE-TEX、保暖（有填充）、硬壳、三合一、软壳、背带裤、电加热 |
| | **中间层、保暖内衣** | 同上 | 美利奴羊毛、上衣/下装/套装 |
| | **手套、袜子、护脸、帽子** | 同上 | 连指手套、皮革、美利奴、电加热 |
| 背包·安全·其他 | **滑雪背包、雪板包、雪崩安全装备、止滑带、打蜡/修板、其他配件** | 均码 | 气囊包、信标/雪铲/探杆/套装、容量(L) |

每个分类有：中文名、所属大类、尺码类型、是否分男女、**强关键词**（英文 + 日文 + 中文，用于纠错）、日本/中国搜索词。

## 4. 数据从哪来（`config/retailers.toml` + `config/categories.toml`）

- **`retailers.toml` 是唯一的“白名单”**：只有写在这里、核验过的网站才会被抓取。每家写了适配器、可信等级（A 大型零售商 / B 专业店 / brand 品牌官网 / caution 谨慎）、价格匹配政策。
- **`categories.toml` 写每家网站“每个分类去哪一页抓”**（`[<网站id>.<分类>]`）。Shopify 店是用 `discover` 工具自动生成再人工检查的（见第 14 节）。

| 抓取方式 | 网站 | 原理 |
|---|---|---|
| Shopify 公开 JSON | evo、Sports Basement、Start Haus、Alpine Shop、Outdoor Gear Exchange、Ski Depot、Aspen Ski and Board、Utah Ski Gear、Cripple Creek、Colorado Ski Shop、Ski Essentials、The Ski Monster、Neptune、Tahoe Mountain Sports、Jans、Campmor、Gorsuch、EMS、9 个双板品牌官网、35 个服装/配件品牌官网 | 店铺公开 `/collections/<分类>/products.json`，一次 250 个商品，含每个尺码的价格和库存，最稳定 |
| 分类页内嵌 JSON | Zappos（只抓滑雪服装） | 分类页（`*.zso`）里的 `window.__INITIAL_STATE__`：品牌、现价、原价、性别、库存数；没有尺码 |
| Salesforce PWA 内嵌 JSON | Marmot 官网 | 分类页里的 `script#mobify-data`（商品搜索结果，含每个尺码的库存）；只抓“滑雪”活动页，Sale 页只用来给这些款式补促销价 |
| 网页解析 | Tactics（默认停用，见下） | 分类页商品格子；原价按“xx% off”反推 |
| REI 分类页 JSON | REI | 分类页加 `json=true` 返回结构化数据；按性别分类页得到男/女/儿童 |
| 网页解析 | Christy Sports、Peter Glenn、Skis.com | 解析分类页商品卡片；**打折商品**再抓商品页取尺码库存（每类有页数上限，控制请求量） |
| 前端搜索接口 | Sun & Ski | 网站自己页面用的公开浏览接口，一次拿到全部尺码价格 |

**默认停用**（原因写在配置里）：The House（原公司 2023 年被清算、投诉多、抓取方式灰色）、Buckman's（和 Skis.com 同一套库存）、Paragon（数据不分品类）、
**Tactics**（2026-09 调查：经营方连年亏损、2025 年被转手，2026 年 4 家门店关了 3 家、正在清库存，近期投诉集中在订单被取消 / 退款被扣钱）。

**人工调查**（`config/due_diligence.json`，80 家，含来源链接）：最初 38 家 + 2026-09-29 补充的 42 家（服装/配件品牌官网、新增雪具店、Zappos、Marmot、Tactics）。
调查中发现的冒充网站：`strafeouterwear.us`（冒充 Strafe，已被注册商停用）、`flylowgear.us`（冒充 Flylow，已失效）；
Stance 2025-11 被 Marquee Brands 收购、网店改由授权商运营，标为“需谨慎”。
Gorsuch、EMS 不卖双板：只抓其他分类（双板分类单独关闭）。
**抓不了**（2026-09 逐家实测，礼貌请求、遇到拦截就停）：Backcountry / Steep & Cheap、Powder7、Amazon、Patagonia、The North Face（第 6 个请求就被 PerimeterX 拦截）、
Columbia、Mountain Hardwear、Helly Hansen、Arc'teryx、Kjus、Sierra、Dick's、Nordstrom（强反爬，工具不绕过验证码）；Orage、Picture 是加元 / 欧元店；Moosejaw 已关闭 → 详情页给一键搜索链接。
抓取器也会识别“返回 200 的挑战页 / 假页面”，连 robots.txt 都被拦截的网站整站当作“被拦截”，不再请求。

## 5. 点一次“更新数据”时发生了什么（`skideals/crawl.py`）

1. 读取注册表 + 分类配置，同步到数据库 `retailers` 表
2. **并行**抓多个网站（默认 6 个线程）；**同一网站内部串行**并限速（`Fetcher` 按域名加锁，遵守 robots.txt 和 Crawl-delay）
3. 每个网站**按分类依次抓**：网站配置 + 该分类的配置 → 适配器 → `RawProduct`
   - 同一个商品可能出现在多个分类页（保暖雪服也在中间层页里）：本次已收过的直接跳过（`seen` 集合）
   - 先把这个分类页的商品收齐，再逐个**判定分类**（第 6 节）：可能改判到别的分类、归为配件，或者不要
   - 双板：早已售罄的老款（比上一季还老）丢弃；其他分类：**售罄的不入库**（服装大多不写年份，没法判断是不是早已下市）
4. 每个“网站 × 分类”抓完后一次性写入数据库（很短的事务，避免 database is locked）
5. 这次没再出现的商品标记为“已下架”——**按来源分类页判断**，所以只抓一个分类不会误伤别的分类
6. 记录每个分类的状态（成功 / 部分成功 / 被拦截 / 出错），显示在「网站可信度」页
7. 全部完成后：更新汇率 → 检查关注列表 → 生成降价提醒、弹 Windows 通知

网页开着时默认每 24 小时自动更新一次（设置里可改）；也可以只抓某些分类：`crawl -c jacket -c goggle`。

## 6. 分类判定（`categories.assign` + `decide_batch`）

**为什么需要**：零售商的分类页并不干净，而且很多标题根本不写品类词。实际遇到的：
- Sports Basement 的“头盔”页其实是“头盔 + 雪镜”，标题只写 “Smith 4D MAG”“Squad + Bonus Lens”；“雪杖”页其实是“雪杖 + 全部配件”（暖手贴、雪镜套、雪橇、防滑垫…）
- Colorado Ski Shop 的雪杖页里混着整套雪板，网址也是复制来的（雪鞋的网址写着 `…-skis-2026`）
- 固定器页里混着刹车片、螺丝、安装模具；雪鞋页里混着烘鞋器、鞋套；雪镜页里混着替换镜片、雪镜套、擦镜布
- 不处理的话，“最便宜的固定器”会是一个 $15 的刹车配件，“头盔”分类里一半是雪镜

**做法：按证据判定，证据从强到弱**（都有单元测试 `tests/test_categories.py`，用的是实际抓到的商品）：
1. **不是滑雪装备 → 不要**：太阳镜、自行车头盔/雪镜、雪橇、雪鞋（snowshoe）、登山杖/健走杖、单板雪鞋/固定器、越野滑雪（XC/Nordic，标题或网站商品类型里写了都算）的板鞋杖蜡、
   雪服页里的雨衣 / 雨裤（rain 后面紧跟衣物词才算：Volcom “Rain GORE-TEX Bib” 是雪裤系列名）、盘子杯子装饰品……
2. **零件 / 配件 → “其他配件”**：刹车、固定器零件、雪鞋内胆/鞋带扣、雪托/杖尖/腕带、头盔护颏/耳机/头盔套、替换镜片、雪镜套、擦镜布、电池/充电器、暖手贴、雪板锁、绑带……
   （防误伤：“Obermeyer Charger Jacket”“Dakine Charger Helmet”是产品线名，“Heated Socks + Batteries”是袜子，“Cable Knit Beanie”是麻花帽）
3. **标题关键词**：每个分类有强关键词（英/日/中），按优先级匹配（雪板包 > 背包 > 雪崩装备 > … > 双板）；MIPS 算头盔，OTG / 低鼻梁版 / 附送镜片算雪镜
4. **网站自己的分类信息**：商品类型、结构化标签（`BreadcrumbClass:Goggles`）、分类路径（Peter Glenn 的 `Shop/Ski/Helmets`）、Christy 的商品分类（`Y SKI CUSHION SOCKS`）、Skis.com 网址里的分类段
5. **选项名**：选项叫 “Frame + Lens” / “Lens Color” 的是雪镜
6. **网址**：只能用来**确认**本页分类，不能用来改判（有的店网址是复制来的）
7. **都没有证据 → 相信分类页**。但如果这一页是**混装页**（有证据的商品里 ≥20% 指向别的分类），没证据的商品直接不要

商品可以被**改判到别的分类**（头盔页里的雪镜 → 雪镜），照样入库。几对分类互相出现属于正常，不改判：雪服↔中间层、中间层里的抓绒裤、保暖内衣里的连体内衣、护脸里的抓绒脖套……
双板页仍用严格的排除表（`NOT_SKI_RE`），因为套装写法太多，改判容易误伤。

**下架判断**也按“来源分类页”算：头盔页里改判成雪镜的商品，由头盔页负责判断是否下架；只抓一个分类不会误伤别的分类。

每次抓取的日志里会打印每个分类页的判定统计（“→goggle 220，不要：混装页里没有证据 41 …”），`python -m skideals audit` 可以随时做一次全库自检（见第 14 节）。

## 7. 同款识别（`skideals/normalize.py`）

同一件东西，各网站写法不一样：
```
Blizzard Black Pearl 88 Skis - Women's 2026         （evo）
Blizzard Black Pearl 88 Women's Skis 2026           （另一家）
Marker Griffon 13 ID Black 90mm                      （品牌官网转卖）
BLIZZARD ブリザード BLACK PEARL 88 (FLAT) 25-26 レディース   （日本）
```
处理步骤：
1. **品牌**：`vendor` 字段或标题开头，查别名表（`Völkl/Volkl/フォルクル` → Völkl），收录了 300 多个雪具/户外/服装品牌
   - 品牌官网也转卖别家商品（J Skis 官网卖 Marker 固定器、Black Crows 官网卖 ATK）：商品 vendor 或标题开头是另一个认识的品牌时，用那个品牌
   - **没收录的品牌**（小众服装、配件品牌有几百个）：从全部网站的 vendor 里**学**（`normalize.BrandRegistry`）——
     去掉 ®™、括号、公司后缀（Inc / LLC / Co. / SRL），全大写/全小写改成首字母大写，同一品牌的不同写法合并
     （`AUCLAIR`→Auclair、`LE BENT` / `Lé Bent`→Le Bent、`Screamer Hats`→Screamer、`thirtytwo` / `Thirty Two`→ThirtyTwo）
   - 网站没给 vendor 时：用学到的品牌名从标题开头认（Christy 的 “Boulder Gear Endurance Jacket”）；
     Skis.com 的网址是“品牌-标题”，标题没写品牌或写错时（“Men's Stormrider 95 Skis”、“Saloomon”）从网址取
   - vendor 写的是店名本身（有的店给服务、二手货填店名）不算品牌；店的自有品牌（evo、EMS、Peter Glenn）要标题也以店名开头才算
   - 实在认不出的显示“未标品牌”（以前显示成空白）
2. **年份**：`2025/2026`、`25-26`、`2026` 都换算成“雪季结束年份” 2026
3. **性别**：标题字样 > 女款专属型号线（Black Pearl、Santa Ana…）> 网站标签 > 网站分类页 > 默认中性；雪镜/头盔/固定器这类不分男女的只认标题里明确的“儿童/女款”
4. **成色**：used / demo / blem / open box
5. **型号 token**：去掉品牌、年份、性别词、品类词（“Skis”“Jacket”）、长度数字、刹车宽度（“90mm”“95-105mm”）、**颜色词**（固定器任何位置；其他装备只去掉末尾的颜色；打蜡用品不去，因为蜡的颜色是温度档），拆开字母数字（`99Ti`→`99 ti`），排序（`M7 Mantra` = `Mantra M7`）
6. **分组键**：
   - 双板：`ski | 品牌 | 型号token | 性别大类(成人/女/儿童) | f 板身 / b 含固定器`
   - 其他：`分类 | 品牌 | 型号token | 性别大类`
7. **规格**（`categories.specs`）：固定器 DIN 范围和刹车宽度、雪鞋 Flex 和楦宽、背包容量、双板腰宽和类型
   - 双板腰宽：先从商品描述（“96mm waist”“131/96/117”）和型号名（Soul **92**）里读；同一型号各网站的值**加权投票**（描述 2 票、型号名 1 票——单个网站的描述会读错，REI 的 Soul 92 读出过 125）
   - 还缺腰宽的，用 `python -m skideals specs`（`skideals/specs.py`）去商品页的规格表里补，结果存在 `spec_cache` 表（按“品牌 | 型号 token”，男女款、含不含固定器共用）。会排除 Sun & Ski 那种“Waist Width (mm) 60 - 79”的筛选分档；商品页被反爬拦截的网站（REI）本次直接跳过；读不到的 30 天后再试
8. **特征标签**（`categories.features`）：GORE-TEX、MIPS、美利奴……从标题/标签里识别；只有“材质类”特征允许从商品描述里读（描述里常有“适合 touring”之类的泛泛之词，会误判）

**年份不进分组键**：同一型号的不同年份放在同一张卡片里、每个报价单独标年份——很多型号连续几年只换配色，买上一季更省钱。

踩过的坑（都修了并写了测试）：`nordic` 误伤品牌 Nordica、`leash` 误伤 Nordica Unleashed、日文浊点被当成变音符去掉、
把 Redster S9/X9 的单字母当噪声删掉会把不同型号合并、“Brake2”这种写法漏过配件识别、“One”尺码没认出是均码。

## 8. 尺码规范化（`categories.norm_size`）

各网站尺码写法五花八门，统一成可以筛选的写法：

| 分类 | 原始写法 | 统一成 |
|---|---|---|
| 双板/雪杖 | `170 cm`、`170`、`46"` | 170（英寸换算成 cm） |
| 雪鞋 | `MP 27/27.5`、`26.5` | 27、26.5（筛选时 26.0 和 26.5 算同一个鞋壳） |
| 固定器 | `Brake 90`、`100mm`、`B100` | 90mm、100mm |
| 服装/手套/头盔 | `X-Large`、`X LARGE`、`Medium Tall`、`M-L`、`YM`（青少年）、`37-38 (S)` | XL、XL、M、M/L、M、S |
| | `4T`、`3-6 MO`、`8L`、`1X`、`55-59CM` | 4T、3-6M、8、1X、55-59cm |
| | `One Size`、`OS`、`Unisize` | 均码 |

认不出的（通常是网站把**颜色/镜片名**当成了“尺码”选项，比如雪镜的 “Sun Black”）不参与尺码筛选，详情里照原样显示。
筛选时“S/M”这种两码合一的，选 S 或 M 都会命中。页面上常用字母码默认显示，数字码/童码/欧码收在“更多尺码”里。

## 9. 固定器专题（`skideals/bindings.py`）

买固定器有三种情况，工具分别处理：

**① 单独买固定器（“固定器”分类）**
- 每款显示 DIN 范围、刹车宽度、GripWalk/MNC/登山标签
- 筛选“我的雪板腰宽”：只显示**刹车宽度在 腰宽 ~ 腰宽+20mm 且有货**的报价（刹车比雪板窄装不上；宽太多会刮雪）
- 按 DIN 上限分档：入门（≤10）/ 进阶（11–13）/ 高级（14–16）/ 专家（≥17）
- 刹车片、零件、安装工具等配件已从固定器里剔除

**② 买“板 + 固定器”套装（双板里的“含固定器”）**
- 识别套装里是哪款固定器（`+ Griffon 13`、`w/ Strive 12 GW Bindings`），记下它的 DIN；
  有的店系统板标题不写 + / with，直接把固定器型号接在板名后面（“Elan Wildcat 80 Ti Shift X EL 9.0”“Head Supershape e-Rally SW+ Prot.”），
  按常见系统固定器型号（EL/ELX/EMX、Protector/PRD、Xpress、NX、M10–M12、FDT、TCX、vMotion…）识别
- 详情页“**套装 vs 分开买**”：同型号板身最低价 + 同款固定器最低价 vs 套装价，告诉你哪个划算
  （例：Rossignol Arcade 84 套装 $799.99；板身 $699.95 + Griffon 13 ID $179.99 = $879.94 → 套装便宜 $79.95，而且大部分店买套装免费安装）
- 固定器价格**只算刹车宽度装得上这块板、而且有货的尺码**：同一款固定器，窄刹车和宽刹车常常价格、库存都不同（evo 的 Griffon 13 ID 卖 $179.97 的只有 110/120mm 刹车，装不到 84mm 腰宽的板上）
- 只有套装版的型号（系统板：固定器装在专用板座上，不能随便换）会注明

**③ 只买了板身，要配固定器（双板里的“板身”）**
- 详情页“**搭配固定器**”：按这块板的腰宽挑刹车合适、有货的固定器，按 DIN 档位各列最便宜的 3 款
- 登山板只推荐登山/多标准固定器，高山板推荐高山固定器；成人板不推荐儿童/青少年固定器（DIN 上限 < 8 的也排除），儿童板只推荐儿童固定器或 DIN ≤ 11 的入门款

购买指南里写了固定器常识：DIN 让雪具店按体重/身高/鞋底长度/水平设定、选固定器让你的 DIN 落在范围中间；GripWalk 鞋底要配 GW/MNC 固定器；单独买固定器再找店安装一般 $50–80。

## 10. 折扣、原价、标签（`skideals/catalog.py`）

- **原价（MSRP）**：同一型号、同一年份，取各店标注原价的**众数**；有品牌官网报价时用官网价
- **折扣** = 1 − 现价 / 原价（统一口径，不用各店自己说的折扣）
- **原价虚高**：某家标的原价比众数高 8% 以上 → 标“原价虚高”
- **历史低价**：当前价 ≤ 我们记录到的最低价，且之前更贵过
- **刚降价**：21 天内降过价
- 分类目录按需生成、按分类缓存；价格走势图用“阶梯线”（历史是稀疏记录的，价格沿用到下一次变化）

## 11. 网站可信度（`skideals/trust.py`）

**① 自动检测**（任何网址都能测，0–100 分，每项都有理由）：域名注册时间（RDAP/WHOIS）、互联网档案馆最早存档（存档中断多年又复活 = 可能是买来的旧域名）、HTTPS 证书、联系方式/政策、Shopify 登记地、全场半价以下、冒用品牌名或已知零售商域名（`utahskigearonline.shop`）、廉价后缀。

“价格远低于市场”只对没收录的陌生网站检查；如果它看起来是某品牌自己的官网（抽查商品 ≥80% 是同一品牌、域名就是品牌名、
域名注册 ≥5 年），官网清仓价比零售店便宜一半很常见，只作提示不扣分（冒用品牌名的新域名照样会被“冒用”检测抓出来）。

**② 人工调查**（`config/due_diligence.json`，80 家，含来源链接）：总部、成立年份、实体店、股权变化、BBB、Trustpilot、常见投诉、退货/运费/价格匹配政策、结论。

「网站可信度」页还显示每家网站**每个分类**的抓取状态和商品数。

## 12. 国际比价（`skideals/intl/`）

- **日本（自动）**：价格.com 搜索，逐条判断是否同款（品牌 + 型号 token + 性别 + 固定器 + 分类都要一致；日文标题也会做分类识别，雪鞋不会配给双板），打开型号详情时查询，缓存 3 天。双板在“スキー板”分类里搜；其他分类用日文品类词（ゴーグル、スキーウェア…）加进关键词搜
- **中国（手动）**：淘宝/天猫/京东要登录、有滑块验证 → 每个分类都给一键搜索链接（用中文品类词）+ “记一笔参考价”
- **汇率**：欧洲央行参考汇率（frankfurter.dev），备用 open.er-api.com，每天一次

## 13. 关注 & 提醒 & 页面（`alerts.py`、`notify.py`、`web/`）

- 在型号详情点“☆ 关注降价”，可设目标价、尺码（双板/雪杖是长度，雪鞋是鞋码，服装是 S/M/L…）、年份。每次更新后：降到目标价，或比上次便宜 3% 以上 → 「关注」页提醒 + Windows 通知
- **找折扣**：顶部分类栏（按大类分组，显示每类款数）→ 男/女/Unisex/儿童 → 左侧筛选（尺码、价格、折扣、特征、分类专属筛选、年份、品牌、成色、网站）；**每个分类的筛选条件分开记住**
- **型号详情**：各网站报价表（每个尺码的库存，你的尺码高亮）、规格、固定器专题（双板）、价格匹配提示、国际比价、价格走势、相近型号
- **购买指南**：买季日历、尺码助手、**装备怎么选**（各分类的选购要点）、省钱避坑、网购骗局、日本/中国购买须知、设置

安全：服务只监听 127.0.0.1；写操作必须带自定义请求头（防 CSRF）；只接受 Host=127.0.0.1/localhost（防 DNS rebinding）。

**界面设计（“Bluebird”设计系统，2026-10）**：Bluebird 是滑雪圈对“雪后放晴的好天”的叫法。
- 颜色全部是 `style.css` 开头的变量：浅色“晴天”、深色“夜场”两套。主题跟随系统，也可以用顶栏按钮手动切换，选择存在 localStorage 的 `sd.theme`。正文和背景的对比度都达到 WCAG AA（≥ 4.5:1）。折扣角标单独用 `--deal-badge`，保证白字可读
- 图标都在 `web/icons.js`：界面图标 + 22 个分类图标 + 北美雪道难度标志（绿圆 / 蓝方 / 黑钻 / 双黑钻）。全部手绘 SVG，不依赖任何外部资源。折扣力度筛选和“搭配固定器”的 DIN 档位都用雪道标志
- 动效在 `web/motion.js`，包括卡片滚动出现、数字滚动、首屏飘雪（Canvas，低密度，看不见时暂停），以及圆环、折线、条形图的入场。系统开了“减少动态效果”时全部关闭
- 手机（≤ 900px）：导航改成底部标签栏 `#tabbar`（它必须在顶栏外面：顶栏的 backdrop-filter / transform 会让里面的 fixed 元素相对顶栏定位）；筛选是底部抽屉；详情底部常驻“去购买”栏；往下滚动时顶栏自动收起
- 无障碍：卡片和可信度表格行可以用键盘打开（回车 / 空格）；详情抽屉打开时其余页面设为 inert，焦点移到抽屉里，关闭后回到原来的卡片；按 `/` 聚焦搜索
- 速度：服务启动后在后台把 22 个分类的目录先算好（`server._warm_catalogs`），目录 JSON 序列化后缓存（`_CATALOG_JSON`），切换分类约 0.1 秒
- 页面入场动画只用 `animation-fill-mode: backwards`：如果结束后保留 transform，里面 position:fixed 的筛选抽屉会跑到屏幕外

## 16. 已知局限

- 价格历史从第一次运行开始记录，走势图需要一段时间后才有意义
- 网页解析类网站（Christy、Peter Glenn、Skis.com）只对**打折商品**抓详情页取尺码，而且每类有页数上限；全价商品只知道有货/无货；
  Zappos、Tactics 的列表页没有尺码，只知道有货
- 服装的同款识别比双板难：同一件雪服在不同网站可能叫法不同（有的带系列名、有的不带），会分成两张卡片；颜色一般不影响分组
- 部分分类只有少数网站在卖（护具 7 家、雪崩装备 10 家），比价空间有限
- 约 14% 的板身不知道腰宽（主要是童板、竞技板，以及商品页上也没写尺寸的型号），这些板没法按刹车宽度推荐固定器；网站自己的规格写错时也会跟着错（抽查 30 个商品页：27 个和已知腰宽一致，1 个是原来的数据错了、商品页才是对的，2 个是网站把别的型号的规格贴了上去）
- 很多大品牌官网有强反爬（Patagonia、The North Face、Columbia、Arc'teryx、Helly Hansen…），只能通过 Zappos、evo、REI 等零售商比价
- 人工调查是某个时间点的公开资料，品牌易手、门店关闭这类变化很快（2025–26 年 Spyder、Volcom 的授权运营商破产，Stance 被收购），下单前再看一眼
- 日本自动匹配偶尔会把配色版、限定版算成同款，详情里会标“待核对”，下单前点链接确认
- 汇率用欧洲央行参考汇率，信用卡实际汇率会差 1–3%
