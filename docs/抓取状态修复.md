# 第二阶段：抓取状态与数据保留

本阶段修复代码与测试，没有回填旧状态，没有重启或中断正在运行的抓取，也没有重新联网采集。

## 行为变化

- Schema.org、品牌官网和 Backcountry 三个适配器保留请求异常的类型与原因；可以继续处理其他入口和商品页，最终由调度器报告真实结果。
- 抓取生成器在中途抛错时，先处理并保存已取得的商品。有保存结果则标记 `partial`，保留失败原因；无结果则按 `blocked`、`robots` 或 `error` 记录。
- 三个通用适配器目前缺乏可靠的完整分页证据，统一保守标记部分覆盖。触及详情或分页预算时补充具体原因，详情链接排序后再截断，避免集合顺序造成随机取样。
- 未出错但最终零产出记为 `empty`（零结果待核查）。可能是真空目录、分类过滤、去重或解析未识别，不能直接判定无货。
- 失败、部分覆盖和零结果均保留未取得的旧商品；已有完整抓取逻辑在正常有产出时仍执行下架判定。
- 网站汇总不再因第一个分类失败而隐藏其他分类的部分产出。网页分类标签、网站状态和进度显示区分部分覆盖与零结果。
- 诊断脚本支持新状态。第一阶段的固定报告保留原样，新生成的报告反映第二阶段代码说明。

## 验证

新增 `tests/test_crawl_integrity.py` 使用临时 SQLite 和假页面，覆盖中途异常、反爬、robots、404、详情失败、多个入口、预算截断、空结果、完整更新及网站汇总。新增前端状态标签回归。

Python 全套 705 项通过；前端报价、分区和抓取状态测试及 JavaScript 语法检查通过。

默认测试临时路径在此 Windows 沙盒中含 `#`，旧有 snapshot 测试的 SQLite URI 拼接无法正确处理。使用工作区内新的测试目录重跑后全部通过；未修改与本阶段无关的 snapshot 实现：

```powershell
.venv/Scripts/python.exe -m pytest -q --basetemp=data/stage2-tests-20261114-a
node --test tests/test_frontend_prices.cjs tests/test_frontend_sections.cjs tests/test_frontend_crawl.cjs

```

`--basetemp` 应指向专用测试目录，pytest 会清理该目录。

## 生效与后续

长时间运行的 Python 进程不会自动重新加载这些修改。当前抓取结束后，重新启动应用或通过新进程运行抓取，才会产生新状态；数据库旧的 `ok + 0` 不会被直接改写。真实站点的成功率仍需下一轮抓取验证。

仍未实现全站分页穷尽判断、真实空目录证据或逐站入口修复。保留旧商品仅防止误下架，不代表其价格仍然有效；报价时效和原价证据属于第三阶段。
